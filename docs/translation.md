# Translation Template

## Purpose

`translation.php` and `translation.phtml` are the shared template parts for the Translation Service UI.

Use them together when a page or layout should expose the framework translation service.

The split exists so applications can keep the required JavaScript and CSS registration while customizing the visible HTML.

## Responsibilities

`translation.php` registers the WebPack assets needed by the translation service:

- `asset:/webpack/js/Translator.js`
- `asset:/webpack/js/Translate_Language.js`
- `asset:/webpack/css/color.css`
- `asset:/webpack/css/Translate_Language.css`

`translation.phtml` outputs the default visible HTML:

- the `Translation Service` heading
- the language selection area with `id="op-translate-language-area"`

The visible HTML may be customized by the application or layout. The JavaScript still needs an element with `id="op-translate-language-area"` because `Translate_Language.js` renders the language selector into that element.

## Usage

Call `translation.php` before rendering the translation service HTML.

```php
<?php if( OP()->Config('execute')['translation'] ?? false ): ?>
	<?php OP()->Template('translation.php') ?>
	<?php OP()->Template('translation.phtml') ?>
<?php endif; ?>
```

Do not call only `translation.phtml` when the language selector must work. That outputs the HTML but skips the WebPack asset registration.

When the default markup is acceptable, use `translation.phtml` so the visible markup has one owner.

When custom markup is needed, call `translation.php` and provide an element with the required language area ID:

```html
<div id="op-translate-language-area"></div>
```

## WebPack Timing

Endpoint templates are executed before the layout head emits the grouped WebPack URLs.

That means a page template can call `translation.php`, register the translation assets, and still have those assets reflected in the WebPack hash generated by `layout/head.phtml`.

Layouts can also call the pair when the translation UI belongs to the shared page frame rather than one endpoint.

## Migration Note

Older versions of `translation.phtml` handled both WebPack registration and HTML output.

The current specification separates the responsibilities:

- use `translation.php` for WebPack registration
- use `translation.phtml` for default HTML output, or provide custom HTML with `id="op-translate-language-area"`

When updating old callers, replace a single `OP()->Template('translation.phtml')` call with the two-call sequence shown above.
